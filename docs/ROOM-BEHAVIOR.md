# Room behavior

## Context and sessions

Each seat has an independent native CLI session and a persisted cursor in `state.json`. Claude uses `--resume`, Codex uses `exec resume <thread>`, and Gemini uses `--resume <uuid>`. Parley launches a CLI process per turn and resumes that native session; it does not keep one CLI process running forever. Stable session IDs and cursors survive a server restart. A provider that omits a stable ID can fall back to its latest session, with a warning.

Ordinary resumed turns receive room entries after that seat's cursor, filtered for delivery rules, plus current instructions and the new message. Parley has no token budget or truncation limit on this unseen delta. A seat absent for many messages can therefore receive a large next prompt. The provider still has its own context window and compaction behavior; Parley does not measure remaining context, control compaction, or guarantee that every earlier detail remains available to the model.

Fresh/recovered sessions receive a briefing and recent history excerpt: at most 6,000 characters across 40 eligible entries, with each entry capped at 1,600 characters. This is an excerpt, not a full-history replay. The room transcript remains on disk, and the briefing tells the agent to consult it when omitted decisions matter. Protected turns can deliberately use isolated fresh sessions. Receipts prevent a restored/older cursor from blindly replaying already delivered history.

Saved room decisions live in a separate `context.json` ledger. Pin a message or add a decision in the room context panel, then edit or remove it there. Agreed convergence handoffs and their nonblocking reservations are saved automatically, once per run and draft version, with their source labeled. When opening a room that has no ledger yet, Parley imports only its most recent existing agreed handoff (with reservations), identified by its persisted convergence metadata. Older agreements and arbitrary chat prose are not imported. This initialization is recorded once, so removing the imported decision stays removed. This is a curated record of important context; it does not automatically summarize every chat message. User pins retain the source message number and author. A complete, current copy of the ledger is injected at the final adapter launch boundary on **every** provider attempt: fresh and resumed sessions, recovery retries, parallel discussion, convergence positions/drafts/reviews, pair work/review, listeners and catch-up. Removed or edited decisions supersede earlier ledger copies in a native session. Saved records supply context and never grant new tool authorization; agent-originated content remains untrusted.

The saved-decision prompt has an explicit 24,000-character budget, including its framing and source labels. The panel reports its usage; this is not a token count or a measurement of the provider's remaining context window. Manual additions/edits that exceed it are rejected without changing the ledger. Automatic agreement records are always retained, even when they cross the budget; the resulting overflow blocks every subsequent provider launch until the user shortens or removes saved decisions. No earlier decision is silently truncated. This guarantees delivery of the current saved ledger to each launched attempt, not that a model will correctly apply every record.

Parley records context lifecycle events with seat, timestamp and reason in the room context timeline and a system transcript notice. It reports its own session resets (settings/permission changes, incompatible saved sessions, missing-session recovery, scratch-room renaming and `/clear`) and Claude's explicit `system` / `compact_boundary` signal. Late signals from a superseded conversation or changed seat configuration are ignored. It never infers compaction from token counts, output length or a changed session ID. Codex exec does not forward compaction in its normal output, so Parley watches only the exact native conversation's saved activity under the CLI's `CODEX_HOME` (or its default home). The observer matches the thread ID in the filename, verifies the session metadata, and records explicit completed `compacted` checkpoints. It reads no unrelated conversation contents. A resumed turn starts at the existing file's end; newly discovered files additionally require a checkpoint timestamp from the current attempt. Checkpoint identities are persistently deduplicated. Partial records wait for their newline, and stale generation/settings callbacks cannot append to a replacement conversation. The panel shows per-seat observation availability; missing, inaccessible, ambiguous, disabled (`--ephemeral`), replaced or oversized session logs produce an explicit visibility limitation while the model turn can continue. This Gemini adapter has no supported internal-compaction signal. Provider-internal changes without readable confirmed evidence cannot be displayed.

Up to 20 previous convergence run snapshots remain inspectable alongside the current run through a refresh, including incomplete/stopped outcomes. A new task disables recovery actions on older runs. The conversation transcript retains agreed handoff entries; `/clear` starts a fresh conversation history while keeping saved decisions and the context lifecycle timeline.

Changing project folder, seat instructions, effective permission scope, Codex sandbox, or applicable Talk/Work mode starts a fresh session for affected seats. Renaming a scratch room also changes its working directory and resets native sessions. `/clear` starts a new conversation and resets every seat's session/cursor while retaining timestamped prior transcript/event files, all saved room decisions, and the context lifecycle timeline. Archive/restore and server restart also preserve the independent context ledger. Archive room instead preserves the whole room, including its current transcript, config, cursor and native session references; restoring puts it back at its original path. The CLI must still have the referenced session on disk.

Source: [provider capabilities, `loadRoom`, `historyTail`, `composePromptDelivery`, config route and lifecycle functions](../parley.mjs).

Codex checkpoint semantics and the on-disk format are verified against the installed CLI's upstream `rust-v0.162.1` source: [wire record schema](https://github.com/openai/codex/blob/rust-v0.162.1/codex-rs/history/src/rollout_payload.rs), [history replacement and checkpoint persistence](https://github.com/openai/codex/blob/rust-v0.162.1/codex-rs/core/src/session/mod.rs#L3856), [completion follows replacement](https://github.com/openai/codex/blob/rust-v0.162.1/codex-rs/core/src/compact.rs#L384), and [canonical activity filenames](https://github.com/openai/codex/blob/rust-v0.162.1/codex-rs/rollout/src/rollout_file_name.rs). The [official app-server documentation](https://learn.chatgpt.com/docs/app-server) likewise distinguishes started and completed context-compaction items; Parley keeps its existing exec adapter. No remaining-context percentage is inferred. The observer limits directory discovery to 50,000 entries, individual activity records to 32 MiB, and the final read to 64 MiB; exceeding a limit marks observation unavailable rather than claiming complete coverage.


## Talk, Work and Auto

Talk uses conservative provider permissions. Work enables the workspace editing policy; provider settings and trusted external CLI configuration still matter. Addressing all agents in a Work room is framed as discussion rather than a shared work order. Protected reviewer/listener turns have provider-specific restrictions; resumed Codex discussion restrictions also depend on workflow instructions.

Auto selects the normal responder from the last-addressed seat and room default; it is a routing choice, not a reasoning level or unlimited autonomy. Explicit `@name` and `@all` choose recipients. Automatic turns are a separate follow-up allowance: new rooms allow four additional provider starts by default; 0 disables those follow-ups and Until settled remains bounded by an emergency ceiling. Existing rooms retain their saved allowance.

## Rosters, archives and Fast mode

New rooms and additions support at most four seats. Existing larger rosters are not silently trimmed; settings can retain or reduce them. Transcript authors retain their original seat names after removal.

Archive room moves an idle room into `.archives`, removes it from active rooms and offers Restore. A busy/queued room must finish or stop first. Default can be archived and stays absent across restarts. Restoring a name already used by an active room fails until that room is renamed. Earlier deleted rooms remain in `.trash` and are not relabeled as archives. `/archive` archives the selected room; `/clear` clears its conversation.

Codex Fast mode is per seat: `serviceTier: "fast"` passes `-c service_tier="fast"`; off persists `"default"` and explicitly passes that value after Extra CLI args, overriding inherited Fast defaults. It applies on fresh and resumed turns without discarding the native session, because service tier is a new-turn setting and does not alter the prompt contract. Account/model availability still determines whether Fast is offered by the provider. Local Codex 0.162.1 accepts both config values; the [official config reference](https://learn.chatgpt.com/docs/config-file/config-reference) documents Fast mapping to the priority request tier.
